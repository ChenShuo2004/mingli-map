# 总知识大纲

## 这份大纲的作用

这是一份持续生长的知识归档目录，用来回答两个问题：

1. 已经收录的知识分别属于哪里；
2. 新仓库进入后，每条知识应该并入哪个既有节点，或在哪个位置建立候选节点。

它不是最终学科分类，也不复制来源正文。实际内容仍分别保存在：

- `data/sources/`：来源原貌；
- `data/comparisons/`：去重、实现一致与分歧；
- `data/knowledge/`：经过整理的正式知识；
- `data/knowledge-outline-index.json`：来源知识模块到本大纲节点的机器可读路由；
- `intake/repositories/`：仓库盘点与处置记录。

大纲负责提供稳定落点和全局视野。真实材料持续进入后，可以拆分、合并或调整节点，但必须记录是什么材料触发了调整。

## 状态标记

| 标记 | 含义 |
|---|---|
| `正式` | 已进入 `data/knowledge/`，有中性表述和来源连接 |
| `比较中` | 已有两个以上实现或来源，正在确认一致、分歧与上游关系 |
| `来源层` | 已忠实保存，但尚未形成正式知识 |
| `待核验` | 缺少可定位原文、独立来源、版本信息或权利信息 |
| `受限` | 已保存但不直接公开，如个人断语、训练语料或高风险结论 |
| `索引` | 只保存位置、范围、哈希和研究线索，不复制正文 |
| `空位` | 大纲预留位置，当前没有足够材料形成内容 |

同一节点可以同时具有多个状态。例如“神煞”可以已有正式阅读框架，同时仍有大量具体规则处于来源层和待核验状态。

## 新知识的归档顺序

每次完成单库知识提取后，逐条执行：

```text
识别真实专题
→ 定位本大纲的最细已有节点
→ 判断是概念、规则、关系、说法、解释、方法/案例还是视觉资产
→ 与该节点已有来源比较并去重
→ 记录一致、补充、差异、冲突或空缺
→ 更新对应节点的来源与状态
→ 满足条件后晋级正式知识
```

归档时优先并入已有节点。只有满足以下任一条件才新增大纲节点：

- 新材料提出了无法被既有节点解释的独立问题；
- 新材料反复出现，已经形成稳定知识簇；
- 塞入既有节点会混淆不同对象、规则或语境；
- 跨体系内容需要独立连接两个以上专题。

不能因为某个仓库自带一个文件名、类名或功能名，就直接增加知识节点。

## 每批收录后的最小更新格式

新内容不把正文堆进本文件，只在最细节点下增加一条简短索引，并把实际数据留在结构化层：

```yaml
outline_id: K-BZ.04.05
item: 新来源中的调候条件用规则
record_type: rule
source_ref: github_owner_repo_commit
comparison_target: 已有十干十二月调候版本
result: supplement | match | difference | conflict | new_candidate
destination: data/sources/... 或 data/comparisons/...
status: 来源层 | 比较中 | 待核验 | 正式 | 受限 | 索引
date: YYYY-MM-DD
owner: 火华与 Codex
```

每批结束必须检查：

- 所有新知识是否都有 `outline_id`；
- 是否误把重复来源当成新知识节点；
- 是否更新了对应节点的一致项、差异项或待核验项；
- 是否出现了足以触发大纲拆分或合并的真实材料；
- 正式知识、受限解释、案例和内部方法是否仍保持分开。

并运行：

```bash
python3 scripts/build-knowledge-outline-index.py
python3 scripts/build-knowledge-outline-index.py --check
```

只有全部来源快照、知识目录条目和正式知识文件都通过路由检查，才能结束本批收录。

若没有实质性新知识、分歧或结构变化，不修改本大纲。
