# 来源与复用规则

## 目的

本项目会接触 GitHub 仓库、古籍、课程、论文、网页和图片。所有知识进入正式数据前，都需要回答：它从哪里来、我们可以怎样使用、它能证明什么。

## 三个必须分开的判断

### 许可判断

确认仓库或资料是否有明确许可证，以及许可证覆盖代码、文档、数据还是整个仓库。没有许可证不等于可以自由复制。

### 来源判断

记录作者是否说明知识依据。一个 GitHub 项目可能只是作者自己的实现，也可能转录古籍、课程或其他数据库；应尽量追溯上游来源。

### 内容判断

即使允许复用，也不能自动视为正确。需要区分：

- 原始材料；
- 作者转述；
- 程序采用的规则；
- 项目自己的解释；
- 多个独立来源能够支持的内容。

### 图像判断

仓库许可证未必自动覆盖仓库中引用的第三方图片、截图、字体和课件素材。每张准备进入知识地图的图片，都要单独确认来源、作者、许可范围和是否可以公开展示。

## GitHub 仓库处理规则

每个候选仓库先建立盘点记录，至少检查：

1. 仓库地址、作者、当前版本或提交；
2. `LICENSE`、README 和数据来源说明；
3. 知识所在文件、目录、数据库或代码位置；
4. 内容是原创、转录、整理还是无法判断；
5. 是否存在上游出处和二次传播风险；
6. 最值得抽取的少量样本；
7. 图解、命盘、截图和其他知识图片的位置与权利状态；
8. 是否包含纯粹增强理解的工具或交互；
9. 暂定处理方式。

暂定处理方式只有四种：

- `reuse`：许可与来源清楚，可以按要求复用；
- `transform`：可在遵守许可的前提下转化为自己的结构与表述；
- `reference_only`：只保留链接、定位和研究线索，不复制内容；
- `exclude`：风险或质量问题明显，不进入项目。

仓库中的辅助理解工具可以单独评估，不必因为外围项目包含测算功能就整体排除。复用工具代码时，需要另外检查代码许可证、第三方依赖、字体与图像素材，并保留原仓库和版本信息。

## 图片归档位置

实际接入仓库后，按来源保存，不把不同项目的图片混在一个公共文件夹：

```text
assets/sources/{source_id}/
├─ original/   # 原始下载文件，不做覆盖修改
├─ derived/    # 裁切、转换、标注等内部处理版本
└─ published/  # 已确认可对外展示的原图、重绘图或重新生成图
```

文件名、校验值和知识关联记录在视觉资产数据中。相同文件只保存一份原件，可以关联多个知识节点。

## 可信度状态

- `unreviewed`：刚发现，尚未检查；
- `located`：已定位内容和出处；
- `single_source`：只有一个来源支持；
- `cross_checked`：已与独立来源核对；
- `disputed`：存在无法合并的不同说法；
- `rejected`：来源或内容质量不足。

这些状态描述我们的核验程度，不给整个知识体系贴“科学”或“不科学”的总标签。

## 争议处理原则

- 发现不同表格、版本、流派或实现相互冲突时，将对应记录标为 `disputed`，不因为存在争议而删除其中任何一方。
- 每种说法分别保留原仓库或书籍、版本 / commit、文件或页码位置、访问日期和差异内容，不用一份“统一表”覆盖原记录。
- 后续通过浏览器检索网页、图书目录、可定位的数字化古籍或现代研究资料，为每种说法补充证据链。检索结果只是线索，不直接替代底本和页码核验。
- 新证据支持其中一方时，更新各说法的核验状态和适用范围，不删除其他版本的来源记录。
- 只有确认为抽取错误、文件损坏或虚构来源时，才将对应说法标为 `rejected`；拒绝对外采用后，仍保留最小来源与判定记录。

## 引用与转述

- 默认优先保存自己的中性转述和准确定位，减少复制大段原文。
- 必须保留原文时，只截取完成核验所需的最小片段，并记录适用许可。
- 图片、课程截图和视频帧默认只作为内部研究材料；对外使用需另行确认权利或重新绘制。
- 仓库自带命盘或其他生成结果时，优先保存生成逻辑、版本、输入参数和结果文件；条件允许时由我们重新生成可复现样例。
- 下载图片时保留原文件，不覆盖或改写；裁切、压缩、标注和重绘版本另存，并记录与原图的关系。
- 公开知识地图只展示标记为“可公开原图”“已重新生成”或“已自行重绘”的资产。
- 删除或失效的网页应保留访问日期和已有定位，但不要假装仍可复核。
